# 0022. OKF v0.2 bundle root: the wiki/ tier, with raw/ outside the bundle

- **Status:** accepted
- **Date:** 2026-07-30
- **Issue:** #189

## Context

#183 adopts the [Open Knowledge Format v0.2](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/3fcbb9f828c2f23d109c855ee403c3a4c81f3a96/okf/SPEC.md) as this repo's `wiki/` page format — a deliberate application of epic #142's buy-vs-build constraint: adopt an existing published format rather than continue shipping a near-miss of one. Spec pin: `GoogleCloudPlatform/knowledge-catalog` `okf/SPEC.md` v0.2 @ commit `3fcbb9f828c2f23d109c855ee403c3a4c81f3a96` (2026-07-24).

Nothing in the repo defines where the OKF **bundle root** is, and that one choice drives provenance, link form, and `raw/` conformance simultaneously. The forcing constraint is spec §11.1: it requires parseable frontmatter on every non-reserved `.md` file *in the tree* rooted at the bundle. This repo's `raw/` tier is governed by a never-edit ("immutability") rule stated in **seven** places, two of them **inside the immutable files themselves** (`raw/karpathy-llm-wiki-agent-memory.md:5`, `raw/beyond-rag-llm-wiki-pattern.md:5`) — so the bundle-root choice determines whether §11.1 ever reaches a file that cannot legally be edited to satisfy it.

`maintain-wiki` and `wiki-librarian` are unreleased (`plugin/CHANGELOG.md`) — there is no installed base and no migration owed by this decision.

## Decision

**The OKF v0.2 bundle root is `<wikiDir>/`** — the directory named by `.gvt-agent.json` `wiki.wikiDir` (`.gvt-agent.json:25`, default `wiki`). **`<rawDir>/` is outside the bundle.**

1. **Bundle root is `<wikiDir>/`.** Concept IDs are page paths relative to it. Stated as `<wikiDir>/`, never hardcoded `wiki/` — this is a shipped plugin contract and a consuming repo may set `wikiDir` to something else. **No `bundleRoot` config key is introduced.** `wikiDir` *is* the bundle root; a second name for one thing is guaranteed drift.
2. **`<rawDir>/` is outside the bundle.** Captures are not concept documents — §11 never reaches them. `sources[].resource` cites a capture as `../<rawDir>/<capture>.md`, which is §6.2's own worked-example form (`../computations/revenue.md` — a relative path escaping the concept's own directory), so this is idiomatic OKF, not a workaround.
3. **The `raw/` immutability rule is preserved intact — no amendment, at any of its 7 sites.** Two latent levers that could otherwise be read as reopening the question are closed explicitly, so a later reader cannot reopen them by inference:
   - **(a)** `raw/README.md:8` and `raw-readme.template.md:8` say "Never edit a file in this directory," which formally sweeps in `raw/README.md` itself — a scaffold artifact copied verbatim from a template, not a capture. The rule draws no capture-vs-scaffold distinction. This imprecision is **known and deliberately untouched** here; nothing in this decision forces the question. Owner: #192, and only if it ever needs to edit `raw/README.md`.
   - **(b)** `docs/wiki-schema.md:92-93` and `wiki-schema.template.md:77-78` justify the rule instrumentally ("This is what makes `wiki/` pages re-verifiable"). That instrumental phrasing is a **rationale, not a carve-out**. Under this decision the question does not arise at all, because captures are not concept documents. Reopening it requires a **superseding ADR**, not an inference from the wording.
4. **Conformance scope.** *Producer:* "OKF v0.2 conformant" means the bundle rooted at `<wikiDir>/` satisfies §11.1–§11.3 — every non-reserved `.md` under `<wikiDir>/`, at any depth, carries parseable frontmatter with a non-empty `type`, and `<wikiDir>/index.md` / `<wikiDir>/log.md` follow §8 / §9 respectively. **Nothing outside `<wikiDir>/` is in scope** — not `<rawDir>/`, not `docs/`, not `plugin/`, not the repo root, not `examples/` or the `*-evals/` harnesses. The claim is always "**the `wiki/` bundle is OKF v0.2 conformant**," never "this repo is." *Consumer (binds `lint` and #150):* a conformant consumer MUST NOT reject for missing optional frontmatter fields, unknown `type` values, unknown additional frontmatter keys, broken cross-links, or a missing `index.md`; and MUST treat a bare `verified` mapping as a one-element list (§5.2). The claim is **not yet true** — today 0 of the 2 concept pages (`wiki/audit-conventions-as-proto-lint.md`, `wiki/llm-wiki-pattern-in-gvt-dev.md`) carry frontmatter. Conformance becomes claimable only when **#192** lands.
5. **`okf_version` placement.** `okf_version: "0.2"` lives in `<wikiDir>/index.md`'s frontmatter, as that file's **sole** frontmatter key. §8: index files carry no frontmatter, with one exception — a **bundle-root** `index.md` MAY carry `okf_version`. §12: that is the only place it is permitted. Under this decision `<wikiDir>/index.md` **is** the bundle-root index, so the legal home already exists — no new file, no new config key. Any `<wikiDir>/<subdir>/index.md` is a subdirectory index carrying **no** frontmatter. `okf_version` is `MAY`, not `MUST`; this bundle **elects** to declare it, because the pin is the whole point of #183 — silent upstream drift is one of its two named standing costs. Written **quoted** — `okf_version: "0.2"` — per §12, which also sidesteps this repo's unquoted-scalar YAML hazard. **#189 decides the home and writes no wiki file**: #190 puts the key in `wiki-index.template.md`; #192 puts it in this repo's `wiki/index.md`.

**Architecture — how this fits ADR-0015.** ADR-0015 (`docs/decisions/0015-maintain-wiki-design-boundaries.md`) rooted `wiki/`+`raw/` outside `docs/` so the two churning tiers escape the `audit-conventions` hygiene walk, and kept `lint` a standalone verb never wired into `audit.mjs`. Both decisions are **reaffirmed**, and the reaffirmation is load-bearing rather than pro forma:

- **Decision 1 (repo-root placement, outside `hygiene.mjs`'s walk).** Verified unchanged: `hygiene.mjs`'s `DEFAULT_EXCLUDE_PATHS` and `listCandidateFiles` walk `docs/**.md` + repo-root `CLAUDE.md` only, so `wiki/` and `raw/` remain structurally outside it. **The inversion this decision avoids:** the rejected repo-root bundle (Compromise, below) would *not* have moved the wiki *into* the curated-docs regime — it would have pulled all 27 `docs/**.md` and 49 `plugin/**.md` files into the **wiki's** OKF format regime, breaching 0015's boundary from the opposite direction while leaving its letter untouched. Choosing `<wikiDir>/` as the bundle root is what makes decision 1's reaffirmation true in rationale, not merely in file layout.
- **Decision 2 (`lint` never wired into `audit.mjs`).** This decision actively protects it: a repo-wide frontmatter property (the repo-root option) would have created standing pressure to add an OKF-conformance check to `audit.mjs`. Scoping conformance to `<wikiDir>/` removes that pressure — an opt-in practice's content health stays out of the plugin-contract gate every consuming repo runs. This bounds **#150**: its conformance walk stays local to the wiki tier and never becomes an `audit.mjs` check.
- **Decision 3 (`ingest` as a thin verb, not a rewrite of `run-retro`/`condense-lessons`)** is untouched by this decision.

## Compromise

Four alternatives were evaluated and declined.

**Bundle = repo root.** Would force frontmatter with a non-empty `type` onto all **102** non-reserved tracked `.md` files, **32 of which already carry frontmatter owned by Anthropic's skill/agent schema** (`CLAUDE.md:100`) — making OKF a co-owner of a block the plugin loader also reads. It would also force a net-new repo-root `index.md` as the repo's *third* table of contents alongside `docs/TOC.md` and `README.md`, because §8/§12 would demote `wiki/index.md` out of `okf_version` eligibility once it's no longer the bundle root. **`claude plugin validate` was probed and does *not* reject an unknown top-level `type:` key** (verified: injecting `type: Skill` into a `SKILL.md`'s frontmatter still passed validation, exit 0) — so this decline rests on distribution-unit and ownership grounds, not on a validator that doesn't actually object: the repo is a **plugin**, distributed as a git-subdir of `plugin/` to the `gvt-plugins` marketplace, and that is the only thing here anyone would actually ship as a knowledge bundle — the repo root is not it. It would also reopen Q2 (how does `raw/`'s frontmatter get added without violating never-edit?) with no clean answer: amending a rule stated in 7 places (two inside the immutable files) is self-contradictory; "re-capture with frontmatter" is self-defeating, because the rule requires leaving the prior capture in place, so the non-conformant originals remain and conformance becomes reachable only by deleting history — which the same rule forbids; a dated grandfather clause makes the bundle conformant by fiat rather than by §11; a capture-vs-scaffold split fixes only `raw/README.md`, 1 of 3 files; and a sidecar stub (below) doesn't satisfy §11.1 for the capture itself. Whichever were chosen, `git log --diff-filter=M -- <rawDir>/` yields a **standing finding that never self-heals**, because the filter reports the *commit*, which stays in history forever. It would also invert ADR-0015 decision 1's rationale and put standing pressure on decision 2, both discussed above.

**Bundle = `<wikiDir>/` with `raw/` mirrored into `wiki/references/` per §6.3.** §6.3 describes a `references/` subdirectory that "conventionally mirrors external material … as first-class concepts within the bundle" — worth a real evaluation, since it would fix Option A's one real cost (provenance sitting outside the distribution unit) by making `sources[].resource` bundle-absolute (`/references/<capture>.md`). Declined on four independent grounds, any one sufficient: (1) it **re-imports Q2 at full strength** — §6.3 makes the mirrored captures first-class concepts, so §11.1–2 apply to exactly the files where it hurts most, paying the repo-root option's price and buying back only the `/…` path form; (2) it **costs a layout migration that dissolves the three-tier vocabulary the plugin is built on** — `raw/` is named in `.gvt-agent.json:26`, `plugin/CONVENTIONS.md:104`, both `metadata.expects` blocks, `raw/README.md`, `raw-readme.template.md`, and the framing at `docs/wiki-schema.md:1-26`; (3) it **silently breaks `lint`'s immutability check** — after a `git mv raw/* wiki/references/`, `git log --diff-filter=M -- <rawDir>/` (`SKILL.md:159`) matches a path that no longer exists, so the check **succeeds vacuously** rather than failing loudly, and a rename is `R`, not `M`, so the filter never sees it either; (4) §6.3 is explicitly "a naming convention, not a requirement," so paying (1)+(2)+(3) to adopt an optional convention inverts the cost/benefit.

**The §6.3 sidecar-stub variant.** A thin `wiki/references/<name>.md` per capture, carrying `type` plus `resource: ../../raw/<capture>.md`, would be OKF-conformant without touching the immutable file — the named **escape hatch** if a consumer ever genuinely needs provenance inside the distribution unit. Declined here because adopting it would need a **superseding ADR**, not a quiet amendment: it doubles the file count per capture, needs its own create/update rule in the schema doc, and duplicates each capture's `**Source:**`/`**Captured:**` metadata with nothing keeping the two in sync.

**Capturing OKF's `SPEC.md` into `raw/` (Q10).** Declined outright, not deferred. A SHA pin achieves Q10's stated purpose — a diffable record so an upstream revision is a tracked migration, not silent drift — more precisely and more cheaply than a 1003-line mirror. It would also be the tier's **first non-summary capture**, contradicting both existing ones: `raw/karpathy-llm-wiki-agent-memory.md` and `raw/beyond-rag-llm-wiki-pattern.md` each explicitly declare themselves "a faithful, attributed summary … not a verbatim mirror," and a *summary* of a normative spec is actively harmful, since it invites a reader to believe they've read the spec. Most decisively: **upstream `GoogleCloudPlatform/knowledge-catalog` is Apache-2.0, while this repo's `LICENSE` is MIT-0** — mirroring is permitted, but it would make this repo's `LICENSE` no longer a complete statement of the repo's licensing, and that is a licensing decision #189 has no mandate to take. The adopted substitute is `okf_version` + the spec URL + the upstream commit SHA `3fcbb9f828c2f23d109c855ee403c3a4c81f3a96`. **No issue is assigned to perform a capture.**

**Explicitly not contradicted:**

- The `raw/` immutability rule at all **7** sites, **byte-identical**: `docs/wiki-schema.md:80-93`; `plugin/skills/maintain-wiki/wiki-schema.template.md:65-78`; `raw/README.md:8-10`; `plugin/skills/maintain-wiki/raw-readme.template.md:8-10`; `plugin/skills/maintain-wiki/SKILL.md:29,159-163`; the verb-contract echoes `docs/wiki-schema.md:126` / `wiki-schema.template.md:111`; and the captures' own self-declarations `raw/karpathy-llm-wiki-agent-memory.md:5` / `raw/beyond-rag-llm-wiki-pattern.md:5`.
- ADR-0015 decisions 1, 2, and 3.
- `.gvt-agent.json` — no schema change; `wiki.wikiDir` doubles as the bundle root.
- `plugin/skills/audit-conventions/**` — untouched.

**Forward-facing consequences:**

- The provenance tier sits outside the distribution unit, so `../<rawDir>/…` **dangles when the bundle is extracted**. §6.1's broken-link tolerance covers *links*, not path-valued fields — a real, if minor, gap. Two producer-side outs exist, named here so #190 doesn't rediscover the wall: the upstream URL is prose in the capture body today (`raw/karpathy-…:3`), and lifting it into capture frontmatter is structurally forbidden by immutability, so the mitigations are (a) a second `sources[]` entry whose `resource` is the upstream URL, alongside the capture entry; or (b) one entry with `resource: ../<rawDir>/<capture>.md` carrying the URL in `title`. **#189 does not pick between them** — it removes the surprise; #190 decides.
- The never-self-healing `lint` finding **does not arise** — no `raw/` file is ever modified.
- **#150 is now buildable**: the conformance walk is exactly `<wikiDir>/**/*.md` minus `index.md`/`log.md` at any level, and §11's consumer clauses bound what it may flag.
- **#191/#150 must not present `raw/` immutability as an OKF rule** — with `raw/` outside the bundle, OKF says nothing about it; `lint`'s check is a purely local convention.
- Naming `<wikiDir>/log.md` a bundle-root reserved file puts §11.3 in force, activating §9's newest-first mandate against `wiki/log.md:3-5`'s append-only wording. Surfaced, not resolved here — #190 owns it.
- The numbering slip: #189's title and AC 1 name ADR-0021, which #194 took instead. This ADR is its own example of the rule already recorded at `plugin/CHANGELOG.md` — do not mint a specific decision-record number into a proposed issue body, because a number parked in a backlog issue is a soft reservation nothing detects going stale.
